# Decapod Security Guarantee-to-Enforcement Matrix

**Status:** Normative Assurance & Drift Contract (`DecapodLabs/decapod#1964`, `DecapodLabs/decapod#1933`)  
**Vocabulary:** `proven_for_exact_subject` · `trusted_assertion` · `conditional` · `not_proven` · `stale` · `failed` · `unsupported`

Cryptographic binding, authenticated identity, locally observed command exit codes, provider-owned CI attestations, independently observed persisted effects, and external forge admission are distinct assurance layers. Passing a local fixture, unit test, or authenticated HTTP request never establishes unverified properties outside that layer's bounded threat model.

## 2. Negative-First & Mutation Coverage Baseline (`#1795` + `#1964`)

1. **`tests/governance_fault_detection_1795.rs` (`#1795`)**: Retains unmodified single-fault mutation checks for `RULE-PROOF-001` (`workunit::validate_verified_manifest`), `RULE-FRESHNESS-002` (`workspace::verify_validation_artifacts_for_publish`), `RULE-POLICY-003` (`readiness_profile::required_source_catalog_with_executor`), `RULE-CUSTODY-004` (`todo::renew_claim_lease`), and `RULE-RETRY-005` (`group_broker::execute_request`).
2. **`tests/security_guarantee_assurance_1964.rs` (`#1964`)**: Extends negative controls and single-fault mutations across previously uncovered boundaries without creating a second governance engine:
   - `RULE-APPROVAL-006` (`src/decapod/core/governed_transition.rs::admit`): removing `request.authorized != *current` staleness rejection is detected by unchanged `governed_transition::tests`.
   - `RULE-CLOUD-PROOF-008` (`src/decapod/core/cloud_proof.rs::assert_candidate_acceptance_envelope`): bypassing subject/fingerprint/state receipt checks is detected by unchanged `cloud_proof::tests`.
   - `RULE-HTTP-READONLY-009` (`src/decapod/core/http_transport.rs`): bypassing `config.read_only_only` RPC allowlist enforcement is detected by unchanged `observability_projections` integration checks.
   - **Drift guard**: fails CI if prohibited absolute security phrasing (unqualified certainty, universal guarantees, or unqualified telemetry assertions) appears in public/normative assurance docs or if an inventory row omits required boundary/assumption metadata.

## 3. Cross-Repository Dependencies & Non-Claims

- **`DecapodLabs/dactyl#158`**: Owns transport/provenance guarantee matrix and live published `dactyl-db` crate vs disposable backend verification.
- **`DecapodLabs/propodus#275`**: Owns server-side distinction between authorized verifier assertions (`independently_verified`) and independently observed execution evidence on deployed Supabase/Edge revisions.
- **No general security certification**: Passing this matrix proves only the explicitly bound fixtures, fault detectors, and source checks recorded for the exact candidate/release revision. Unconfigured hosts, unmediated shell escapes, admin ruleset bypasses, and unverified external deployments remain outside kernel enforcement.
